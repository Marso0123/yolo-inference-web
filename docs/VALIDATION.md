# 验证范围

以下为开发机在 2026-10-14 发布准备前已有的功能验证，不代表每台电脑都已验收。

环境：Windows x64、GTX 1660 SUPER（6GB）、Python 3.11、PyTorch 2.6.0+cu126、ONNX Runtime GPU 1.22.0、Ultralytics 8.4.175。

## 已执行

- YOLOv8n、YOLO11n、YOLO26n 的检测／实例分割，各执行 PT／ONNX × CPU／GPU，共 24 个实际推理组合。
- 六个官方 nano 模型实际完成 PT → ONNX 导出、图检查和 CPU 推理检查；测试图片上的类别与数量一致。
- 一份用户自训练检测模型完成网页上传、GPU 推理、截图和 PT → ONNX 检查。该权重与原始素材不公开。
- 视频预览、WebSocket 帧序号、H.264 手动录制与时长；本机 MediaMTX H.264 RTSP 的断线清帧、停止录制与重连。
- 类别过滤的勾选、搜索、恢复全部、模型区分和重启恢复。
- 新增批量导出：YOLO11n 检测／分割 × PT／ONNX × CPU／GPU，共 8 个实际组合。使用同名图片、空白图和故意损坏的图片，检查原图字节、图片／标签对应、归一化坐标、空标签、错误报告、ZIP 下载与内容完整性。
- 导出的检测／分割标签通过当前锁定版本 Ultralytics 的训练标签校验器；没有为验证格式启动模型训练。
- 浏览器实际完成文件夹选择（含子目录）、多图选择、忽略非图片、原类别 5 → 导出类别 0、ZIP 文件链接下载。
- 实际 CPU 批量取消：30 张输入，在完成 1 张后取消，仅保存已经完成的图片／标签对。
- `pytest tests`：18 项检查通过，涵盖会话控制、类别偏好、标签格式、取消、错误、方向规范化、ZIP 和 API。

ONNX GPU 检查实际推理 profiling 中的 CUDA 执行节点；PT GPU 检查模型参数的设备。页面显示耗时包含模型调用的预处理与后处理，不代表摄像头到浏览器的完整延迟。

## 尚需使用者验证

真实摄像头网络和码流、自训练模型识别准确率、不同显卡与驱动、长时间运行、超大图片集合、磁盘耗尽及 Linux／macOS 部署。空标签不证明图片没有目标；自动预标注需要人工复核后用于训练。

原始开发机验收材料包含本地路径和素材信息，未上传公开仓库。README 提供验证脚本用法，使用者可在自己的电脑生成对应报告。

## 2026-10-16 录制流畅度修复验证

- 自动检查共 28 项通过，新增源视频帧率、连续帧、RTSP 新画面时间戳、写盘不锁住状态接口、低速推理、H.264／MJPEG 录制起点竞态等回归检查。
- 本地视频录制改为逐帧处理所选源视频片段，输出保持源视频帧率；推理速度不足时预览放慢，保存片段按源时间播放。普通预览仍可跳过旧帧。
- 使用开发机自训练分割模型和 1080p 视频测试片段：源约 24.50855 FPS，保存为 24.509 FPS，36 帧逐帧编号连续，片段长约 1.469 秒。处理与编码耗时约 8.219 秒，验证了处理较慢时也不丢源视频帧。模型和测试媒体不公开。
- GPU 检测：50 FPS 输入，48 帧全部保留，H.264 输出为 50 FPS、0.96 秒。
- 手动停止录制并继续预览：30 FPS 输入，所选 12 帧连续保留为 0.4 秒片段。
- 本机 MediaMTX H.264 RTSP：输出 25 FPS、51 帧、约 2.04 秒；断流时清除旧画面并结束保存录制。
- 测试片段带有逐帧编号，解码保存文件检查编号连续性；既检查文件帧率，也检查实际画面，避免仅提高文件标称帧率。

RTSP 仍取决于实际接收和推理速度，不能通过补重复帧恢复未完成推理的实时画面；本次没有进行真实摄像头现场验收。旧录制文件中已经跳过的帧需要从原始视频重新推理录制。
